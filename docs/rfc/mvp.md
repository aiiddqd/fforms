**RFC: WordPress-плагин «fforms»**  
*(рабочее название — fforms)*

### Критерии приёмки MVP

- [ ] Зарегистрированы CPT `fform` и `fform_entry`, формы имеют JSON-схему и тип `contact`/`lead`.
- [ ] Публичный REST submit валидирует данные по схеме и сохраняет приватный entry.
- [ ] Публичные REST endpoints отдают опубликованные формы и схемы; entries защищены capability.
- [ ] Работают honeypot и rate limit.
- [ ] Динамический Gutenberg-блок выбирает и отправляет опубликованную форму.
- [ ] Работают уведомление администратору, опциональный автоответ и настраиваемый SMTP.
- [ ] Администратор может просмотреть entries, изменить статус и выгрузить CSV.
- [ ] PHP и JavaScript проходят синтаксические проверки.

### 1. Цель и позиционирование

**fforms** — лёгкий, headless-friendly плагин для приёма, хранения и обработки данных из форм в WordPress.

Он закрывает три основных сценария использования:

1. **Контактные формы и сбор лидов**  
   Классические «Напишите нам», заявки, обратная связь, подписка.

2. **Формы редактирования / создания контента на сайте**  
   Фронтенд-формы, через которые пользователи (или редакторы) могут создавать/обновлять записи, страницы, кастомные типы постов, мета-поля и т.д. без захода в админку.

3. **Анкетирование и опросы**  
   Сбор структурированных ответов, сохранение результатов, аналитика, экспорт.

Ядро остаётся тем же:  
сообщения/ответы хранятся как Custom Post Type → уведомления по почте (с SMTP) → приём через REST API (Gutenberg + headless).

### 2. Кому это нужно и какие боли закрывает

| Сценарий | Аудитория | Боль | Как fforms помогает |
|----------|-----------|------|---------------------|
| Контактные формы + лиды | Агентства, малый бизнес, лендинги | Заявки теряются, уходят в спам, нет единого архива | CPT + SMTP + статусы + REST |
| Headless / Astro / Next | Разработчики JAMstack | Нужен простой endpoint для форм без тяжёлых плагинов | Чистый REST + CORS + схема формы |
| Фронтенд-редактирование контента | Членские сайты, порталы, UGC, внутренние системы | Пользователи должны создавать/редактировать записи без доступа в wp-admin | Форма → валидация → создание/обновление поста через REST/API |
| Анкетирование / опросы | HR, маркетинг, исследования, курсы | Нужно собирать структурированные ответы и потом анализировать | Отдельный тип формы + результаты как CPT + экспорт + простая аналитика |

### 3. Архитектура (обновлённая)

#### 3.1. Ядро — два связанных CPT

- `fform` — сама форма (шаблон / схема)
  - Настройки: тип формы (`contact` | `lead` | `content` | `survey`)
  - Поля (JSON-схема)
  - Поведение после отправки (уведомление, создание поста, редирект и т.д.)
  - Права доступа

- `fform_entry` (или `fform_message`) — каждая отправка / ответ
  - Связь с формой
  - Данные полей (JSON)
  - Статус, источник, IP, user_agent
  - Для content-форм — ссылка на созданный/обновлённый пост
  - Для survey — возможность агрегации

#### 3.2. Типы форм и разное поведение

| Тип формы | Что происходит при submit | Дополнительно |
|-----------|---------------------------|---------------|
| `contact` / `lead` | Сохраняется entry + письмо админу (+ auto-reply) | Статусы new/read/replied, быстрый ответ |
| `content` | Сохраняется entry + создаётся/обновляется пост/страница/CPT | Маппинг полей формы → post_title, content, meta, terms |
| `survey` | Сохраняется entry | Аналитика, экспорт, возможность анонимности |

#### 3.3. REST API (расширенный)

```
POST   /wp-json/fforms/v1/submit
GET    /wp-json/fforms/v1/forms
GET    /wp-json/fforms/v1/forms/{id}
GET    /wp-json/fforms/v1/forms/{id}/schema
GET    /wp-json/fforms/v1/entries          (с правами)
POST   /wp-json/fforms/v1/entries/{id}/status
```

Для content-форм дополнительно:
- возможность указать `post_type`, `post_id` (для редактирования), `status` (draft/publish) и т.д.

#### 3.4. Конструктор (Gutenberg)

- Блок `fforms/form`
- Внутри — блоки полей
- В настройках блока выбирается тип формы и поведение
- Для content-форм — визуальный маппинг «поле формы → поле поста»
- Для survey — типы вопросов (одиночный/множественный выбор, шкала, открытый ответ)

### 4. Roadmap (обновлённый)

**v1.0 — MVP**
- CPT `fform` + `fform_entry`
- Типы: contact / lead
- SMTP-настройки + уведомления
- REST submit
- Базовый Gutenberg-блок
- Honeypot + rate-limit
- Экспорт CSV

**v1.x**
- Тип `content` (создание и редактирование постов через форму)
- Тип `survey` (базовое анкетирование)
- Статусы + быстрый ответ
- reCAPTCHA / Turnstile
- Webhooks (Telegram, Slack, Make, n8n)

**v2.0+**
- Условная логика полей
- Multi-step формы
- Загрузка файлов
- Аналитика опросов (графики, сводки)
- Роли и права на уровне форм
- AI-автоответы / саммаризация ответов
- Интеграция с WooCommerce, CRM, membership-плагинами
- GraphQL-поддержка
- Визуальный конструктор в админке (drag-and-drop) как альтернатива Gutenberg

### 5. Ключевые технические решения

- Все формы и все ответы — данные первого класса внутри WordPress.
- Поведение формы определяется её типом + настройками, а не хардкодом.
- REST API — основной способ приёма данных (Gutenberg-блок тоже ходит через него).
- Content-формы работают через стандартные WordPress capabilities + дополнительные проверки.
- Survey-формы хранят ответы в удобном для агрегации виде (можно потом считать NPS, распределение ответов и т.д.).

### 6. Название и бренд

- **Плагин**: fforms  
- **Text Domain**: `fforms`  
- **Namespace**: `FForms\`  
- **CPT**: `fform`, `fform_entry`  
- **REST**: `fforms/v1`

Коротко, запоминается, не конфликтует с существующими крупными игроками (Formidable, Fluent Forms и т.д.).
