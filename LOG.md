Формат записи:

```

- краткое описание изменения
- ...
```

## 2026-09-12

- RFC `headless-main-form`: встроенная главная zero-config форма (`key: main`) и лояльный маршрут `POST /fforms/v1/form` с плоским payload, данными вне схемы и вложениями — черновик доведён до полного шаблона RFC.
- Голый embed-документ сбрасывает `height`/`min-height`/`overflow` у `html` и `body`: стили темы делали body скролл-контейнером во фрейме, из-за чего документ сообщал высоту фрейма вместо своей и форма обрезалась со внутренней полосой прокрутки.
- Исправлена обрезка формы во фрейме: высота измеряется по контенту, а не по `documentElement`, повторно отправляется, пока фрейм ей не соответствует, и ставится inline-стилем поверх CSS темы; убран `scrolling="no"`, чтобы ошибка измерения не резала контент молча.
- Публичная форма получила «голый» режим `?fforms_embed=1` — документ без шапки, подвала и админ-бара для вставки во фрейм; сниппеты iframe и js-script теперь ведут на него, а обычная ссылка `/forms/{id}` осталась полной страницей для шаринга.
- Точный URL фрейма передаётся в `data-fforms-src`, чтобы скрипт не угадывал слеш в permalink и не ловил лишний 301.
- Базовая спецификация дополнена разделом 7.2 про внешнюю вставку формы через iframe и js-script.
- В боковой панели формы собраны все точки вставки: шорткод, публичная ссылка, iframe и js-script; iframe и js-script показываются только для опубликованной формы в режиме «Share via URL».
- Публичная страница формы во фрейме сообщает свою высоту родителю через `postMessage` (`assets/public-form-frame.js`); вне фрейма репортер не активируется.
- Добавлен `assets/embed.js` — вставка формы на сторонний сайт: скрипт подставляет iframe публичной страницы формы и подгоняет высоту по `postMessage`.
- Базовая спецификация дополнена разделом 7.1 про шорткод `[fform id=123]`, политику недоступной формы и подключение ассетов.
- Отлажен сквозной сценарий вставки: блок и шорткод на обычной странице дают одинаковую разметку, уникальные DOM id, 201 на отправке, 422 с ошибкой поля и ложный успех на honeypot.
- Зафиксировано, что `/services/wwdb` рендерится шаблоном темы `code-driven` в обход `the_content()`, поэтому сценарий прогнан на обычной странице; исходное содержимое страницы восстановлено.
- Сообщение о недоступной форме стало настраиваемым: `Form_Renderer::render_form()` принимает `$unavailable_notice`, общая политика «гость — пустота, редактор — сообщение» вынесена в `editor_notice()`.
- Содержимое формы теперь разворачивает шорткоды внутри окна guard'а рекурсии, поэтому `[fform id=X]` внутри формы X отдаёт сообщение о циклической ссылке вместо литерального текста.
- В боковую панель формы добавлено поле с готовым шорткодом `[fform id=<ID>]` для опубликованной формы режимов `block`/`public`.
- Добавлен шорткод `[fform id=123]` (`includes/class-shortcode.php`) как тонкая обёртка над `Form_Renderer::render_form()` с ранним и поздним подключением ассетов формы.
- Удалены мёртвые legacy-ассеты `assets/block-editor.js`, `assets/view.js`, `assets/view.css`, не подключавшиеся ни из одного PHP-файла.
- Добавлен RFC `docs/rfc/form-embed-block-and-shortcode.md`: вставка формы блоком и шорткодом `[fform id=123]`, отладочный сценарий на живой странице, удаление мёртвых legacy-ассетов.

## 2026-08-30

- Удалены тестовые PHP-fixture и config-флаг; Headless API E2E теперь создаёт и публикует форму только через wp-admin.
- Блоки FForms перенесены в отдельную категорию редактора; поля скрыты вне CPT формы, а Headless API принимает только блоки полей и серверно отклоняет другую структуру.
- Разрешено REST-сохранение protected meta формы пользователям с `edit_post`, устраняя ошибку публикации `_fforms_type` в Gutenberg.
- Корневой `fforms/headless-schema` стал серверным инвариантом headless-режима, защищающим REST и запрет встраивания при устаревшем значении mode-meta.
- Headless API теперь редактируется через жёстко заданный Gutenberg-блок `fforms/headless-schema` с блоками полей; JSON-textarea удалён, а `_fforms_schema` компилируется как производный REST-кэш.
- Отмечены проверенные критерии конвертации режимов в RFC.
- E2E-сценарий открывает свёрнутую панель Headless API перед проверкой сериализованной схемы.
- Объединён E2E-сценарий создания и переключения режима, чтобы использовать единый авторизованный контекст wp-env.
- Добавлен безопасный fallback на стартовую схему при обратной конвертации некорректного headless JSON в блоки.
- Переключение режима теперь обновляет block-editor store напрямую, не давая Gutenberg повторно добавить форму из шаблона.
- Предотвращена повторная вставка шаблона Gutenberg при переходе в Headless API.
- Обновлены E2E-тесты и базовая спецификация для переключения режима в боковой панели без экрана выбора.
- Добавлен переключатель режима в боковую панель с преобразованием Block editor ↔ JSON-схема Headless API.
- Убран специальный flow `post-new.php`; репозиторий схем теперь явно использует JSON для headless-режима.
- RFC скорректирован по ручным тестам: режим выбирается в боковой панели, а новые формы создаются как обычные Block editor.
- Отмечены выполненные функциональные критерии RFC и задокументировано отдельное ограничение глобального JS-lint.
- Отформатирована панель настройки Headless API по правилам ESLint/Prettier.
- Зафиксировано ограничение полного `lint:js`: проверка изменённых JS-файлов проходит, а глобальный обход проекта требует отдельной настройки ignore-путей.
- Block editor снова создаётся с каноническим стартовым набором блоков при явном создании draft после выбора режима.
- Приведён новый E2E-спек выбора режима к правилам форматирования JavaScript.
- Уточнена диагностика lint-конфигурации для zsh без ложного падения на отсутствующем `.eslintrc`.
- Зафиксирована и устранена нестабильность E2E-запуска, начатого до обновления селекторов карточек режима.
- Обновлены E2E-проверки создания формы: существующий smoke-сценарий явно выбирает Block editor, добавлены сценарии выбора режимов и headless-редактора.
